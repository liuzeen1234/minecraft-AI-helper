# 刻的应用与时序速查

> 目标版本：Java 版 1.20.4。基础定义（游戏刻/区块刻/随机刻/计划刻/红石刻/活塞刻）见 `刻.md`。本文提供应用层面的换算表、时序实例与 1.20.3+ 新增的 `/tick` 命令用法。

## 单位换算速查

| 单位 | 时长 | 关系 |
|---|---|---|
| 游戏刻（gt） | 0.05 秒（50ms） | 1 秒 = 20gt |
| 红石刻（rt） | 0.1 秒（100ms） | 1rt = 2gt |
| 活塞刻 | 0.05 秒 | 等于 1gt（以方块事件阶段划分） |
| 1 秒 | 20gt | 10rt |
| 1 分钟 | 1200gt | 600rt |
| 1 个游戏日（昼夜） | 24000gt = 20 分钟 | — |

## 常见红石元件延迟表（Java 版 1.20.4）

| 元件 | 延迟 | 备注 |
|---|---|---|
| 红石粉 | 0 | 信号即时传播（无延迟） |
| 红石火把 | 1rt（2gt） | 熄灭/点亮各 1rt |
| 红石中继器 | 1–4rt（2–8gt） | 档位调节，右击切换 |
| 红石比较器 | 1rt（2gt） | 后/边侧输入同 |
| 侦测器 | 1rt（2gt） | Java 版固定 1rt |
| 活塞（推/拉到位） | 0–2gt | 启动即时；到位约 2gt 内（活塞刻理论见刻.md） |
| 发射器/投掷器 | 1gt | 激活后 1gt 射出物品 |
| 拉杆/按钮 | 0 | 拉杆 0、按钮木 30gt/石 20gt 脉冲 |
| 压力板 | 0 | 实体离开后约 1rt（2gt）复位 |
| 漏斗 | 每 8 刻传输 1 个物品 | 每 8gt 一次尝试吸取/传输 |
| 音符盒 | 0 | 被激活立即发声（激活延迟同活塞） |
| 门/活板门/栅栏门 | 0 | 即时开关 |
| 标靶 | 2gt | 命中后 2gt 输出 |
| 避雷针 | 0（8gt 脉冲） | 被击中输出 8gt 信号 |
| 铜灯（1.21 实验） | 1gt 激活 | 记忆锁存，脉冲切换 |

## 信号传播与衰减

- 红石粉信号强度 15 起始，每经过 1 格衰减 1，降到 0 停止；信号最长传输 15 格。
- 红石中继器/比较器可"中继"信号重新满 15。
- 强充能 vs 弱充能：见 `方块总览与通用特性.md`（中继器/比较器输出强充能，红石粉输出弱充能）。

## 计划刻实例（行为时序）

- **TNT**：激活后 4 秒（80gt）爆炸。
- **沙子/沙砾**：被下方方块破坏/活塞推动后成为下落方块实体，落地后变回方块。
- **水与熔岩**：流体流动以计划刻进行（每 gt 更新流动方向，流速见方块篇）。
- **红石中继器**：Java 版中继器改变状态延迟 1rt，且"熄灭"优先级 -2、"点亮"优先级 -1（见刻.md 优先级）。
- **命令方块（循环型）**：每游戏刻执行一次。
- **计划刻优先级**（Java 版）：-3（中继器指向红石二极管背面/侧面）→ -2（中继器熄灭）→ -1（中继器点亮、比较器指向二极管）→ 0（其他）。最大每刻处理 65536 个计划刻。

## 0 刻与 BUD

### 0 刻（Zero-tick）
- 活塞伸出的前 0–1gt 内（方块事件处理阶段），活塞头尚未完全到位，但侦测器/中继器等"即时更新"元件已响应——可产生 0 刻脉冲/0 刻移动。
- 常见应用：0 刻甘蔗/竹子/玄武岩机（1.20.4 中多数已修复? 0 刻作物机在 1.16+ 基本失效，但 0 刻移动（活塞链）仍可用于实体/方块瞬移类装置，需按版本验证）。
- 注：0 刻是社区术语（即时更新理论），详见 `刻.md` 活塞刻。

### BUD（Block Update Detector）
- 利用侦测器/活塞等对"未预期方块更新"的响应检测变化。
- Java 版 1.20.4：侦测器侦测**方块状态变化**（非普通更新），是主要 BUD 手段；活塞 BUD（半连接）在 1.19+ 已大部分修复? 活塞准连接（half-connection）在 1.20 仍存在部分场景，需实测。
- 用途：检测作物生长、TNT 激活、隐形更新等。

## 随机刻应用（作物与铜氧化）

- 默认 `randomTickSpeed=3`：每区块每区段每 gt 随机选 3 个方块。见 `刻.md`。
- 作物平均生长周期（Java 版，含光照/湿润条件）：小麦约 5–35 分钟? 精确数值受条件影响大；随机刻间隔中位数 47.3 秒。
- 铜块氧化：每随机刻有概率进入下一氧化阶段（未涂蜡）；用蜜脾涂蜡可锁定。
- `/gamerule randomTickSpeed 0` 可关闭随机刻（作物停止生长、铜不氧化）；设为 0 可防止幻翼生成? 幻翼生成不受此影响。

## /tick 命令（1.20.3+ 新增，1.20.4 可用）

- 用途：管理员调试刻运行与性能；**需要权限等级 2+**；默认不在命令方块与数据包中可用。
- 语法：
  - `/tick query`：查询当前目标刻速率与性能信息。
  - `/tick rate <数值>`：设置目标 TPS（如 `20`、`100`、`1`），游戏按此速率推进。
  - `/tick freeze`：冻结游戏刻（实体/方块停止更新，玩家仍可移动与放置）。
  - `/tick step <次数>`：仅在冻结时使用，逐刻推进指定次数后再次冻结（调试用）。
  - `/tick step stop`：停止逐刻，回到冻结状态。
  - `/tick unfreeze`：解冻，恢复所有游戏元素运行。
- 注意：修改 TPS 影响所有依赖刻的机制（红石、作物、生成），仅用于测试/调试；`/tick rate` 值过高会导致 TPS 下降（性能瓶颈）。

## TPS 与 MSPT 实操

- 正常 20TPS；每刻预算 50ms。MSPT 超过 50ms 时 TPS 自动下降。
- 调试屏幕（F3）显示 MSPT（"ms ticks"）；Alt+F3 图表显示 TPS。
- 卡顿排查：漏斗数量、红石时钟、大量实体 AI、区块生成（见 `刻.md` 常见诱因）。
- 服务器命令：`/perf`（性能分析）、`/debug`（调试记录）、`/jfr`（JFR 分析）见命令集文档。

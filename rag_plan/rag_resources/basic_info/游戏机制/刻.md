# 刻（Tick）

Minecraft 由一个大的程序循环驱动，循环的一个周期称为一**刻（tick）**。

## 游戏刻

绝大多数运算在一个大循环内执行，执行一次循环即为一刻，即**游戏刻（Game Tick，gt）**。

- 游戏默认以每秒 20 刻的速率运行，一刻为 0.05 秒（50 毫秒）。
- **每秒刻数（TPS）**衡量运行速度；可通过 `/tick rate` 修改默认值。计算机性能不足时 TPS 会下降。
- **每刻毫秒数（MSPT）**是服务器完成一刻计算的实际耗时。仅当 MSPT ≤ 50 时 TPS 才能维持 20。Java 版调试屏幕（F3）显示 MSPT；Alt+F3 可查看 TPS 图表。

常见服务端卡顿诱因：

- 漏斗持续检查上方是否有物品——用容器方块或堆肥桶盖住可停止检查，或用水运输散装物品。
- 红石机构，尤其红石粉会导致大量方块更新、亮度更新；关闭闲置红石装置和时钟、减少空气空间可缓解。
- 生物 AI——用照明控制怪物生成，使用更高效的养殖技术。

### 游戏流程（Java 版，每个循环周期依次处理）

1. 执行带 `tick` 或 `load` 标签的函数。
2. 按主世界、下界、末地顺序，对每个维度：
   - 发送时间至客户端；更新世界边界；处理天气逻辑；处理玩家睡眠逻辑。
   - 若为主世界：增加游戏内时间和天数；执行计划内函数。
   - 对每个已加载区块：发送区块信息至客户端；执行区块刻逻辑。
   - 尝试生成幻翼、灾厄村民、猫和僵尸围城。
   - 发送实体变更至客户端；尝试卸载区块。
   - 处理计划刻（方块的计划刻、液体的计划刻）。
   - 处理袭击逻辑；尝试生成流浪商人；处理方块事件；处理实体；处理方块实体。
3. 处理玩家实体。
4. 若已过去 6000 刻，尝试自动保存。
5. 处理来自客户端的数据包。

## 区块刻

每个游戏刻会对特定区块处理区块刻：

- Java 版：加载类型为强加载**且**中心与非旁观玩家水平距离小于 128 方块的区块，每游戏刻处理一次（Y 轴位置无关）。
- 基岩版：每个游戏刻内，所有已加载区块都会处理。

区块刻触发的行为：

- 生物自然生成。
- 雷暴天气下有 1/100000 概率在区块内某处生成闪电。
- 每列最顶端方块有 1/16 概率检查天气更新：寒冷生物群系结冰、降雪盖雪层（含炼药锅接雪/雨水）。
- 区块内一定数量方块受到随机刻处理（见下）。

## 随机刻

- Java 版：每个游戏刻，区块每个区段默认随机选出 `randomTickSpeed` 个方块给予随机刻（可用 `/gamerule randomTickSpeed` 调整，默认 3）。同一方块可能被多次选中。
- 基岩版：每个游戏刻每区块随机选出 `区段数 × 2.5 × randomTickSpeed` 个方块给予随机刻（默认 1）。

受随机刻影响的方块行为：

- 农作物生长/拔除；蘑菇传播/拔除；藤蔓传播。
- 火生起或蔓延。
- 冰、雪层融化；树叶枯萎；耕地湿润度更新。
- 仙人掌、甘蔗、海带、竹子、紫颂花、甜浆果丛生长。
- 草方块、菌丝体传播或退化。
- 树苗长成树；熔岩点燃附近方块。
- 发光红石矿石熄灭；下界传送门方块可能生成僵尸猪灵。
- 海龟蛋破裂/孵化；营火冒烟。
- 紫水晶母岩长出紫水晶簇；铜块进一步氧化；滴水石锥填充下方炼药锅。

Java 版中两次随机刻间隔的中位数为 47.30 秒（946.03 游戏刻），方块平均每 68.27 秒（1365.33 游戏刻）更新一次。

## 计划刻

方块可请求在未来某游戏刻更新自身，这种方式称为**计划刻**，用于必定发生且可预测的变化（如红石中继器计划一刻后变化状态、水流动时计划刻）。

Java 版计划刻分两种，处理顺序先按优先级、再按计划顺序（优先级越小越早执行）：

- 红石中继器：若指向红石二极管背面/侧面 → 优先级 -3；若准备熄灭 → 优先级 -2；否则 → 优先级 -1。
- 红石比较器：若指向红石二极管背面/侧面 → 优先级 -1。
- 其他所有方块计划刻：优先级 0。
- 方块计划刻处理完后处理液体计划刻（无优先级，仅按计划顺序）。

处理上限：Java 版每游戏刻最多处理 65536 个计划刻；基岩版每区块每游戏刻最多处理 100 个。

## 红石刻

**红石刻（Redstone Tick，rt）**= 2 游戏刻，约 1/10 秒，最初定义为 1 档红石中继器的延迟。

- 基岩版：红石刻是并发存在的游戏机制，直接影响红石信号传递。
- Java 版：红石刻不是真实存在的独立机制，是社区总结的术语，因为大部分红石元件延迟是 2gt 的整数倍。

## 活塞刻（仅 Java 版）

即时更新理论认为活塞启动延迟为 0，从实体阶段到方块事件阶段属于一个游戏刻（以方块事件阶段结束划分），这种划分方式称为**活塞刻**。音符盒发声延迟与活塞相同（0 活塞刻）。计划刻元件按活塞刻计的延迟不固定。
